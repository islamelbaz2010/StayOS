## 4. Property Acquisition

### 4.1 Source 1: Founder Network (Weeks 1-3)

| Metric | Target |
|--------|--------|
| Contacts called | 20 |
| Meetings held | 10 |
| Listings created | 6-8 |
| Conversion rate | 30-40% |

**Script:**
> "أنا بطلع منصة جديدة للشقق المفروشة في مصر، مخصصة للسوق المصري. عمولة أقل من إير بي آند بي، صرف أسرع، ودعم بالعربي. أول 3 حجوزات بدون عمولة، وصور احترافية مجانية. عندك شقة تحب تضيفها؟"

**Translation:** "I'm launching a new platform for furnished apartments in Egypt, built for the Egyptian market. Lower commission than Airbnb, faster payout, Arabic support. First 3 bookings commission-free, free professional photography. Do you have an apartment to add?"

**If yes:**
1. Schedule a visit within 3 days.
2. Take 10+ photos (or send a photographer).
3. Collect KYC documents (ID + selfie + ownership proof).
4. Create listing from the web form.
5. Upload photos.
6. Submit for review.
7. Approve from admin queue.
8. Send WhatsApp: "تم نشر شقتك! تقدر تشوفها على: [link]"

### 4.2 Source 2: Property Management Companies (Weeks 1-4)

| Metric | Target |
|--------|--------|
| Companies contacted | 10 |
| Meetings held | 5 |
| Companies signed | 2-3 |
| Listings imported | 15-25 |

**Pitch:**
> "StayOS charges 8% commission for managed portfolios (vs 15-20% on Booking.com). We bulk-import your units via CSV. Arabic-first platform for local guests. Faster payout. Dedicated WhatsApp support."

**Process:**
1. Meet company. Show platform demo.
2. Sign simple agreement (1 page: commission rate, payout terms, exclusivity optional).
3. Company provides CSV with unit details.
4. Founder validates CSV.
5. Import via admin CSV upload.
6. Founder uploads photos manually (company sends via WhatsApp/email).
7. Founder reviews and approves each listing.
8. Listings go live.

**Key assumption:** 50% of listings come from agencies and developers (B2B), not individual hosts. This is realistic for Egypt where property management companies control significant inventory.

**If supply falls behind:**
- Week 4 and < 10 listings: Founder drops everything and does manual seeding. Create listings from Facebook/OLX research.
- Week 5 and < 20 listings: Extend alpha to 8 weeks. Consider paid host acquisition (EGP 500/listing).
- Week 6 and < 30 listings: Convene committee. Consider whether the supply model is viable.

## 6. Guest Acquisition

### 6.1 First 10 Bookings (Weeks 3-6)

| Method | Target | Conversion |
|--------|--------|------------|
| Founder personal calls to 50 warm contacts | 5-7 bookings | 10-15% |
| Facebook travel groups (organic post) | 1-2 bookings | 2-5% |
| WhatsApp broadcast to warm contacts | 1-2 bookings | 5-10% |

**Total: 7-10 bookings**

**Script for warm contacts:**
> "عملت منصة جديدة للشقق المفروشة في القاهرة الجديدة، مكتوبة بالعربي، تدفع بالجنيه المصري، وكل العقارات متوثقة. أول 10 ضيوف لهم خصم 15% وبرجاء مجاني. تحب تجرب؟"

**Translation:** "I built a new platform for furnished apartments in New Cairo, written in Arabic, payment in EGP, all properties verified. First 10 guests get 15% discount and free cancellation. Want to try?"

### 6.2 Guest Booking Process (Manual for Alpha)

1. Guest expresses interest via WhatsApp.
2. Founder sends direct listing links (not search page — too thin).
3. Guest selects a listing and dates.
4. Founder creates booking via admin/API.
5. Guest pays via:
   a. Paymob iframe (if working), OR
   b. Bank transfer (founder confirms manually).
6. Booking confirmed.
7. Guest checks in. Founder sends check-in instructions via WhatsApp.
8. Guest checks out. Founder sends thank-you message + asks for feedback.
9. Founder processes payout to host within 48 hours.

## 7. Manual Operations

### 7.1 Payment Processing

| Scenario | Process |
|----------|---------|
| Paymob iframe works | Guest pays online. Booking auto-confirmed via webhook. |
| Paymob fails / not ready | Guest transfers to StayOS bank account. Founder checks bank statement every 2 hours. Founder confirms via `POST /admin/bookings/{id}/confirm-payment`. |

### 7.2 Payout Processing

| Step | Process |
|------|---------|
| 1 | After guest checks out, founder calculates payout: booking total - platform commission - payment processing fee = host payout. |
| 2 | Founder transfers to host's bank account via online banking. |
| 3 | Founder records payout in spreadsheet: date, host, amount, bank reference. |
| 4 | Founder sends WhatsApp to host: "تم تحويل مبلغ [X] جنيه. رقم العملية: [ref]" |

### 7.3 KYC Review

| Step | Process |
|------|---------|
| 1 | Founder opens admin KYC queue. |
| 2 | Reviews ID document (front + back) and selfie. |
| 3 | Checks: ID is valid, photo matches selfie, name matches listing owner. |
| 4 | If approved: click Approve. Host receives SMS. |
| 5 | If rejected: enter reason. Host receives SMS. Founder calls host to explain. |

### 7.4 Listing Review

| Step | Process |
|------|---------|
| 1 | Founder opens admin listing queue. |
| 2 | Reviews: title (Arabic), description, photos (5+), price (reasonable for area), location (correct coordinates). |
| 3 | If approved: click Approve. Listing goes live. Host receives SMS. |
| 4 | If rejected: enter reason (e.g., "needs more photos", "price too high"). Host receives SMS. Founder calls to help fix. |

## 8. Escalation Decision Tree

```
Issue occurs
├── Technical bug?
│   ├── Founder can reproduce? → Report to engineering via Slack with steps + screenshot.
│   ├── Platform down? → Call CTO immediately. Engineering on-call.
│   └── Data corruption? → Stop platform. Call CTO. Restore from backup.
├── Payment issue?
│   ├── Guest paid but booking not confirmed? → Check Paymob webhook. If failed, confirm manually via admin endpoint.
│   ├── Guest wants refund? → Process refund via bank transfer. Update booking status. Record in spreadsheet.
│   └── Host didn't receive payout? → Check bank transfer status. Re-process if needed. Call host to explain.
├── Trust issue?
│   ├── Guest says property doesn't match photos? → Call guest immediately. Call host. Mediate. If host at fault, suspend listing.
│   ├── Guest damages property? → Document. Mediate. Guest pays for damages directly to host. StayOS does not accept liability.
│   └── Fraud suspected? → Suspend listing. Freeze host account. Investigate. Report to committee.
├── Host issue?
│   ├── Host wants to delist? → Unpublish listing. Thank them. Ask for feedback.
│   ├── Host complains about no bookings? → Check listing quality. Check price. Personally find a guest for them.
│   └── Host wants to edit listing? → Guide them via WhatsApp or do it for them via admin.
└── Guest issue?
    ├── Guest can't find listing? → Send direct link. Don't make them search.
    ├── Guest can't pay? → Offer bank transfer. Walk through process.
    └── Guest wants to cancel? → Process cancellation. Refund per policy. Update host.
```

## 10. Founder Rules

1. **Never skip morning calls.** 2 hours of host outreach every morning is non-negotiable. No calls = no supply = no marketplace.
2. **Never approve a listing without photos.** A listing without photos damages the marketplace.
3. **Never approve KYC without checking the ID.** Trust is the differentiator. Don't compromise it.
4. **Never let a payout exceed 48 hours.** Host trust depends on fast payment.
5. **Never stop talking to guests.** Every guest who books, call within 24 hours of checkout. Collect feedback. Offer discount on next booking.
6. **Never build anything.** If a process can be manual, keep it manual. Engineering builds only what's in `02_SPRINT3_EXECUTION_LOCK.md`.
7. **Never go a day without logging metrics.** If it's not measured, it didn't happen.
8. **Take 1 day off per week.** Burnout kills startups. Rest is a strategy.
