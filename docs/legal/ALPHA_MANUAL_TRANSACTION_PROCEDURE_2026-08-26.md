# ALPHA_MANUAL_TRANSACTION_PROCEDURE_2026-08-26.md

**Scope:** Transactions 1–10 of the StayOS V1 closed alpha.  
**Principle:** Every step below can be executed manually; no automated escrow, split payout, refund, or ownership verification is claimed.

---

## 1. Guest Booking

1.1. Guest browses/search listings on web or mobile.  
1.2. Guest selects dates and guest count, submits a booking request.  
1.3. System creates a booking in `requested` status. No payment is required yet.

**Manual?** No — existing code handles this.  
**Owner:** System / Guest.

---

## 2. Host Acceptance

2.1. Host (or admin, for founder-sourced first listings) reviews the request.  
2.2. Host accepts the booking; system moves it to `accepted`.  
2.3. **24-hour payment clock starts.** If the Guest does not submit payment proof within 24 hours, the Host or admin may cancel the booking.

**Manual?** Host acceptance is manual; 24-hour deadline is not enforced by an automatic timer in V1 — admin must monitor.  
**Owner:** Host / Admin.

---

## 3. Payment Instructions

3.1. System displays manual payment instructions to the Guest, including:
- StayOS-controlled bank account number (real account to be provided by Founder).
- Vodafone Cash number (real number to be provided by Founder).
- A unique reference number for the transfer.
3.2. Guest must transfer the total amount: accommodation subtotal + cleaning fee + 4% guest service fee (unless the Guest is within the first 10 completed guest bookings globally, in which case the service fee is 0%).

**Manual?** Guest transfer is manual; instructions are generated by the system but the real account details must be configured by Engineering once Founder provides them.  
**Owner:** Guest / System / Founder (for account details).

---

## 4. Payment Proof Upload

4.1. Guest uploads a screenshot or PDF of the transfer receipt.  
4.2. System stores the proof and notifies admin.

**Manual?** Guest upload is manual; system storage uses S3 (currently the same public-read bucket as listing photos — a privacy gap to be fixed).  
**Owner:** Guest / System.

---

## 5. Admin Verification

5.1. Admin reviews the payment proof against the bank/Vodafone Cash statement.  
5.2. Admin checks the reference number for duplicates.  
5.3. Admin either verifies or rejects the proof.
- **Verified:** booking moves to `confirmed`.
- **Rejected:** booking returns to `pending`; Guest may resubmit up to 3 times within 48 hours of the first rejection. After that, the booking is cancelled.

**Manual?** Fully manual in V1.  
**Owner:** Admin.

---

## 6. Booking Confirmation

6.1. On verification, system updates booking status to `confirmed` and emits notifications.  
6.2. Guest receives confirmation with booking details.

**Manual?** No — existing code handles this.  
**Owner:** System.

---

## 7. Commission Calculation

7.1. Admin manually computes Host payout from the accommodation subtotal, applying the alpha incentive:
- **If this is one of the Host's first 3 completed bookings:** Host payout = subtotal − 2% platform take = 98% of subtotal.
- **All other bookings:** Host payout = subtotal − 10% host commission − 2% platform take = 88% of subtotal.
7.2. Guest service fee is not part of the Host payout calculation; it is collected from the Guest and retained by StayOS (waived for the first 10 completed guest bookings globally).

**Manual?** Yes — computed by hand for transactions 1–10.  
**Owner:** Admin.

---

## 8. Host Payout

8.1. Within 3 business days of payment verification, admin transfers the computed net amount to the Host's bank or Vodafone Cash account.  
8.2. Admin records the payout in the manual ledger.

**Manual?** Yes — manual transfer and ledger entry.  
**Owner:** Admin.

---

## 9. Cancellation by Guest

9.1. Guest initiates cancellation through the app.  
9.2. Admin determines the applicable tier:
- **Flexible:** 100% accommodation refund if cancelled ≥24 hours before check-in.
- **Moderate:** 100% accommodation refund if cancelled ≥5 days before check-in.
- **Strict:** 50% accommodation refund if cancelled ≥1 week before check-in.
9.3. The 4% guest service fee is **non-refundable** if the Guest initiates the cancellation, regardless of tier (waived for the first 10 completed guest bookings globally; if waived, there is no service fee to refund).

**Manual?** Tier application and refund computation are manual in V1.  
**Owner:** Admin.

---

## 10. Cancellation by Host / StayOS / Property Unavailable

10.1. If the Host cancels, StayOS cancels, or the property is unavailable/inaccessible, the Guest receives a **100% refund of everything** — accommodation amount + guest service fee.  
10.2. StayOS retains no commission on the cancelled booking.  
10.3. A Host who cancels 2 or more confirmed bookings during the alpha triggers a manual admin review of their listing(s).

**Manual?** Yes — refund approved and executed manually.  
**Owner:** Admin.

---

## 11. Refund

11.1. Once a refund is approved, admin transfers the refund amount back to the Guest's original payment source within **5 business days**.  
11.2. `refund_days` in the cancellation notification template must be set to `5` before this is used on a real cancellation.

**Manual?** Yes — manual transfer and ledger entry.  
**Owner:** Admin.

---

## 12. No-Show

12.1. **Guest no-show:** Host declares it; admin confirms via support contact. No refund of accommodation amount or service fee.  
12.2. **Host no-show / property inaccessible:** Treated as Host failure — 100% Guest refund.

**Manual?** Yes — no-show is declared and confirmed manually.  
**Owner:** Host / Admin.

---

## 13. Duplicate Payment

13.1. If a Guest accidentally pays twice, admin identifies the duplicate during proof review by matching reference numbers/amounts.  
13.2. Admin refunds the extra amount to the original payer within the standard 5-business-day refund timing.

**Manual?** Yes.  
**Owner:** Admin.

---

## 14. Accounting / Reconciliation

14.1. For transactions 1–10, maintain a simple manual ledger (spreadsheet) with:
- Booking ID
- Guest amount received
- Guest service fee (if any)
- Host commission (if any)
- Platform take (2%)
- Host amount paid
- Refund amount (if any)
- Dates of verification, payout, refund
14.2. Reconcile against bank/Vodafone Cash statements weekly.

**Manual?** Yes — spreadsheet is sufficient for 1–10 transactions.  
**Owner:** Admin / Founder.

---

## 15. Exception Handling

15.1. Any case not covered above (e.g., novel disputes, edge-case refunds after Host payout) is resolved by the Founder on a case-by-case basis for the first 1–10 transactions.  
15.2. If a pattern recurs, it is formalized into policy.

**Manual?** Yes.  
**Owner:** Founder.

---

**End of Alpha Manual Transaction Procedure.**
