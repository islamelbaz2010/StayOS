## Purpose

This article provides production-ready communication templates for every common support scenario. Every template is bilingual (Arabic primary, English below), designed for WhatsApp, and calibrated to match StayOS's voice: warm, direct, and solution-focused. Use templates as a starting point — personalize names, amounts, and specifics before sending.

---

## Background

Templates serve two purposes: speed (agents don't write from scratch under pressure) and consistency (every guest gets the same quality response regardless of which agent handles their case). Templates fail when they're used robotically — a template with the wrong name or wrong amount is worse than no template at all. Always read before sending.

---

## Core Concept: Template Categories

```
Category A: Pre-Stay (booking confirmation, check-in prep)
Category B: Check-In and Access (key codes, address, lockouts)
Category C: Mid-Stay Issues (maintenance, complaints, emergencies)
Category D: Checkout and Post-Stay (checkout instructions, reviews, refunds)
Category E: Host Communications (payout, listing, performance)
Category F: Dispute and Resolution (dispute acknowledgment, outcomes)
Category G: Escalation and Emergencies (lockouts, safety, critical issues)
```

## Template Usage Rules

1. **Personalize before sending**: Replace ALL [placeholders] with actual data before hitting send.
2. **Send Arabic first, English below**: The format above is the correct order.
3. **Bold critical information**: Use *asterisks* for key numbers, times, and codes in WhatsApp.
4. **One template, one situation**: Don't combine multiple templates into one message. If the situation evolved, use the appropriate next-stage template.
5. **Check amounts before sending**: A payout notification with the wrong amount is worse than no notification.

---

## Template Maintenance

**Who adds templates**: Any team member who resolves a new type of issue not covered here.
**When to add**: After the 3rd time you write the same response from scratch.
**How to propose**: Submit the template to the Support Lead for review and inclusion here.
**Review cycle**: Monthly — remove unused templates, update amounts and SLAs if they've changed.
